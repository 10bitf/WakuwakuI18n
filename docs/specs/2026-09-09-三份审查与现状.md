## 2. 三份审查的读数

### 2.1 收益侧：两笔账，两笔都不成立

**① 翻译工具链不需要 Paraglide。**

inlang 的架构是：**inlang 工程**（`project.inlang/settings.json` + 存储插件）是真源，
编辑器（Fink / Sherlock）读它，Paraglide 只是**另一个消费它的编译器**。

证据在我们自己刚写的文件里：`WakuwakuDark/project.inlang/settings.json` 的 `modules`
**只有 `@inlang/plugin-icu1`，没有 Paraglide**；Paraglide 是 `astro.config.mjs` 里一个独立的
Vite 插件。依赖方向是 Paraglide → 工程，不是工程 → Paraglide。
inlang 官网把 Paraglide 列为 Fink 的 "complementary, **not required**"。

**所以「留着自己的编译器 + 加一个 `project.inlang/`」能同时拿到两样东西。** 代价是 11 行 JSON。

⚠️ **这一条还没有端到端读数**（没有真的用 Sherlock 打开一个没装 Paraglide 的仓库编辑一次）。
它现在是「架构上成立 + 官方文档支持」，不是实测。**动任何东西之前先把这一条量掉。**

**② 跨语种完整性早就在跑，不是迁移的收益。**

`src/check.js:94` 起就在做：某 key 在 base 有、别的语种没有 → `released` 语种直接 error；
每个复数变体单独比占位符。迁移文档 §9 把它写成「本次迁移新增的唯一实质能力」——**假的**。
真正新增的只有「中文表禁复数语法」那一条守卫，而那条**根本没写**（见 2.3）。

### 2.2 成本侧：Racing 上买到的是零

审查用 **Racing 自己的 rollup** 打了一份与 Paraglide 产物同形的 917 条消息表，只用其中 10 条：

| 调用形态 | 产物里剩多少条 | 产物大小 |
|---|---|---|
| `m['a.b.c']()` 字面量索引 | **10 / 917** | 2.5 KB |
| `import { "a.b.c" as k }` | **10 / 917** | 2.5 KB |
| **命名空间挂 `globalProperties`** | **917 / 917** | 274 KB |
| **动态索引 `m[变量]()`** | **917 / 917** | 274 KB |

而 Racing：

```
<script setup> 文件数: 0        .vue 总数: 94
src/main.js:12  app.config.globalProperties.t = t
```

**Options API 的 `<template>` 看不见模块作用域的 import。** 所以 Racing 只能落在第 3 行 ——
除非把 379 处模板取词全搬进 `computed`，或者 94 个组件改写成 `<script setup>`。
再叠上 61 处动态 key（第 4 行），tree-shaking 在 Racing 上**实测为零**。

而迁移文档 §6.1 拆掉「命名空间 = 文件名」这道挡板的**唯一对价**就是 tree-shaking。
**挡板拆了，替代品拿不到。**

尺度也小：i18n 载荷 50,552 字节 / 主包 js 合计 990,664 字节 —— **上限 5%**。

### 2.3 那道说好「必须有」的守卫没写

迁移文档 §8.1 写着「第 2 条**必须有守卫**，不能靠记性」（指「中文表不许写 plural 语法」，
写了会把 `Intl.PluralRules` 拖进小程序包）。`check.js` 里一行 `plural` 都没有。

更要紧的是审查指出的这句：

> **迁移会把现存的那道闸删掉（`compile.js` 的 `allowIntl`），而替代品从未写出来，中间没有重叠期。**

### 2.4 我给的数字，错了三次

| | 我写的 | 实测 | 差 |
|---|---|---|---|
| 全仓动态 key | 7 处（0.6%） | **110 处（9.1%）** | 15× |
| Racing 调用点 | 354 | **586** | 漏了 177 处 `this.t('…')` |
| Racing 文案条数 | 926 | **933** | — |

动态 key 那次是**只扫了 `t(\`a.${x}\`)` 模板拼接，漏了 `t(变量)`**（key 从数据里来，
`t(act.titleKey)` 这种）。而这 110 处正是最难迁的部分：Racing / Photoman 是 JS + Vue **没有
TypeScript**，拿不到 WakuwakuDark 那种 `Record<联合类型, …>` 的穷尽性保证，
漏登记一条的表现是真机上某个页面白掉。

### 2.6 我的判断出了什么问题

审查给的形状比我自己想的准：

> **记分规则在翻转前后不对称。** Paraglide 不满足「缺语种要红」→ 处理是「我们自己补上」；
> 自建不满足「翻译工作流」→ 没有人问「那我们自己补一个 inlang 工程行不行」，
> 而答案是 11 行 JSON。**同一条规则对两个候选用出两个结果。**

上午那四条价签，真正被新读数解掉的只有两条（序数、文案格式），一条换了个说法（polyfill 体积），
一条**直接接受**（调用点改动）—— 而那正是上午判负的主因。

三次翻转的淘汰理由属于同一类缺陷：**拿一个没验证过的前提去淘汰对手。**

1. 07-28：用一条对所有候选都成立的理由淘汰 i18next
2. 09-09 上午：拿一次尝试的失败当能力边界（说 Paraglide 序数是坏的、文案表要换格式 —— 都错）
3. 09-09 下午：拿一个未验证的耦合假设（编辑器绑引擎）淘汰自建编译器

### 2.7 家法违反

- **造轮子闸门**：上午的对比表里**没有 Paraglide 这一行** —— 六周前刚选过又退回的头号候选。
  它是被用户提起才补测的，而补测发生在实现代码落地之后。

## 4. 现在成立的裁定

1. **停掉 Racing 的 Paraglide 迁移。** 依据是 §2.2 的三行 rollup 读数与「`<script setup>` 用了 0 个」——
   是读数不是推理。收益在 Racing 上实测为零，代价是 586 处调用点 + 8 个消费方碎 + 2 道守卫炸 +
   1 道守卫静默失效 + 缺 key 从留白变白屏。

2. **不是「换不换引擎」的二选一，是「哪个项目适合哪个引擎」。**
   这回到了 `icu-compile-design.md:219` 我自己写下、下午没论证就推翻的那条：
   > **不要为了统一而现在就动它们。** 今天动只有风险没有收益，而风险是取词路径坏掉这种全站级别的。

   | 项目形态 | 适不适合 Paraglide |
   |---|---|
   | Astro + TypeScript + 静态站（WakuwakuDark ✅ 已验，Wakuwaku、Dirty） | 合适：字面量索引能摇、有 TS 穷尽性、构建期取词、产物可逐字节验收 |
   | uni-app + Options API + 无 TS（Racing、Photoman） | **不合适**：tree-shaking 拿不到、穷尽性拿不到、缺 key 从留白变白屏 |

3. **WakuwakuDark 保留 Paraglide。** 它已经验过，且正是合适的场景。

4. **库的身份定死了（v0.9.0）：文案的校验层，取词是可选零件。**
   `@messageformat/*`（725 KB）挪成**可选 peer 依赖** —— 不用编译器的项目一个字节都不下（实测
   WakuwakuDark 依赖图里 0 个、Racing-7 里 5 个）。引擎差异收进 `src/check.js` 的 `ENGINES`
   一张表，由 `i18n.config.mjs` 的 `engine` 字段显式声明，**加引擎是加一行不是改逻辑**。

5. **`compile` / `make-t` 不删。** README 那句「迁完就删」要改 —— Racing / Photoman 如果留在自建
   编译器上，那两个入口就是它们的取词层，不是过渡态。

## 7. 这一天最该记住的一条

**三次翻转，三次都是「拿一个没验证过的前提去淘汰对手」。**

判读表里那条「**这个数有没有第二种解释**」，我一直用在测量上，**没有用在自己的推理上**。
下一次做选型对比表时，每一行的「不用它的理由」后面要能立刻回答：
**这条理由是读数还是推断？** 是推断就先去量，不要写进表里当结论。
